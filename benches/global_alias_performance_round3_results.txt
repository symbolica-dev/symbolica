Ownership optimization
----------------------
Single-owner alias copies/appends bypass recursive collection. Multi-owner
contexts are sorted uniquely by full generation-aware token, with binary
searches and deduplication before Arc cloning. Subtree copies retain only
referenced dependencies; detached byte views retain registry fallback.
Ownership discovery now keys its collection by token, avoiding body hashing
while retaining distinct handles with semantically equal bodies. Ordinary
child subtrees can be skipped, while mutation paths still handle a temporarily
stale root alias flag. The experimental identity-hash.patch was NOT USED.
Public AliasHandle Eq/Hash was not replaced with that proposed shortcut.

Expression-key contract and API change
-------------------------------------
Atom, AtomView, AtomOrView, and typed compound expression keys compare and hash
transparent aliases as their bodies. Opaque aliases retain token identity.
No-alias keys use encoded bytes. Alias expansion preserves dirty flags and
stored structural metadata, rebuilding normalized sum order as needed.
Equality/hashing do not normalize expressions or invoke user callbacks.
Equal expressions provide identical hash write sequences for arbitrary hashers.
Public Eq/Ord/PartialOrd agree, including metadata distinctions. The inherent
AtomView::cmp remains the normalization comparator.

Borrow<[u8]> cannot satisfy this semantic expression-key contract. Its
replacement is Borrow<BorrowedAtom>, including the KeyLookup bound. A map
query now uses:

  use symbolica::atom::BorrowedAtom;
  expression_map.get(BorrowedAtom::new(expression.as_view()))

Evaluation, zero-test, and legacy alias-map queries have been migrated.
RawAtom and the global alias store's AliasKey retain byte-oriented keys.

Normalization and convergence
-----------------------------
Numeric aliases participate correctly in sums, products, and powers. Flat,
linear, builtin, argument-splicing, and custom-normalized functions expose
transparent argument shapes when needed. Ordinary functions preserve alias
compression when no such rule applies, and opaque aliases remain opaque.
Rebuilding requires a raw representation change; an outer custom normalizer
runs once. Key comparisons/hashes remain callback-free.
Representation-sensitive convergence/change checks use raw bytes in
alias_known_aliases, repeat_map, Transformer::Repeat/IfChanged, replacement,
and legacy alias expansion, so alias-only rewrites are retained.
