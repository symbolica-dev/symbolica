Performance hot paths: normalization, expansion, and replacement
Experiment date: 2026-10-25

Baseline and scope

The baseline is clean upstream main at 1a1829b1. Both variants use the same
benchmark harness and resolved Cargo.lock. The optimized variant adds only the
four source changes in benches/performance_hotpaths.patch. Earlier measurements
on a development checkout are excluded from these results.

The reproduction script copies the checkout into a temporary directory, reverses
the patch for baseline, then reapplies it for optimized. Keep the patch in sync
with the source. The script preserves the working checkout and retains its
binaries, build logs, and raw measurements for inspection.

Changes under test

Symmetric and antisymmetric normalization sort borrowed arguments and rebuild
the function once, removing per-argument atom copies. Antisymmetric permutation
parity uses a linear cycle walk. Duplicate handling, wildcard behavior, and
custom normalization callbacks are preserved.

Multinomial expansion reuses temporary atoms, skips exponent-one wrappers for
normalized arguments, and combines exact multinomial coefficients before product
normalization. Floating-point, finite-field, other unsupported coefficient
domains, and dirty inputs retain the previous coefficient order. Dirty arguments
also retain exponent-one normalization, including custom function callbacks.

Replacement computes upcoming wildcard-length bounds without an intermediate
Vec. Restrictions, greedy/non-greedy match order, repeated and optional bindings,
and upstream's partial-match bounds check retain their existing behavior.

Four inline hints on RecycledAtom::from, wrap, deref, and deref_mut expose these
small wrappers across codegen units. They address additional out-of-line wrapper
calls observed during development with the non-LTO bench profile.

Method

Harness: examples/performance_hotpaths.rs (18 cases).
Host: AMD EPYC 9754 128-Core Processor, x86_64.
Compiler: rustc 1.98.0 (88d9e12ae 2026-08-18), cargo 1.98.0. Default features.
Native dependencies: nix-shell -p gcc gnumake m4 python313 pkg-config.
Builds and tests: 8 jobs, pinned to CPUs 32-39.
Timings: one benchmark process at a time, pinned to CPU 126; SMT sibling 382.

The measured bench profile uses opt-level 3, 16 codegen units, LTO off,
incremental compilation, debug assertions off, and CARGO_PROFILE_BENCH_DEBUG=0.
Release with LTO is supported by the script but was not measured for this PR.

Each case runs baseline and optimized consecutively, alternating their order by
case and pass. Each invocation warms up once, then reports the median of seven
samples lasting at least 100 ms each. Each sample divides elapsed wall time by
completed operations. Results use the median of three pass medians.
Time change = 100 * (optimized / baseline - 1); speedup = baseline / optimized.

Normalization clones a prepared FunctionBuilder and finishes it. Expansion runs
expand/expand_in on prepared inputs. Replacement runs on a prepared 256-function
input. Output construction and destruction are included. Output byte counts,
expected replacements, polynomial expansion cross-checks, and regression tests
check correctness. Plain normalization, product expansion, and no-match
replacement are controls. These microbenchmarks do not establish application
speedups or measure allocations directly.

Reproduction

From the optimized checkout, with Rust and native dependencies available:

  env -u HOTPATH_CASE -u HOTPATH_ITERATIONS HOTPATH_CPU=126 HOTPATH_PROFILE=bench HOTPATH_PASSES=3 HOTPATH_SAMPLES=7 HOTPATH_MS=100 bash benches/performance_hotpaths.sh

Choose an idle physical core appropriate to the host and check its
thread_siblings_list in sysfs. The script does not reserve a CPU. Set
HOTPATH_PROFILE=release to compare the repository's LTO release profile.

Validation

1042 library unit tests and 3 pattern_matching integration tests passed;
1 library test remained ignored. Regression coverage includes argument
permutations, antisymmetric duplicates/wildcards and callbacks, exact multinomials,
finite-field simplification, floating-point order, dirty inputs, and wildcard
restrictions and match order.

Command: CARGO_PROFILE_BENCH_DEBUG=0 cargo test --profile bench --lib --test pattern_matching -j 8.
The patch reverses byte-for-byte to the four upstream source files and reapplies
byte-for-byte to the optimized sources. Rustfmt and diff whitespace checks pass.
