-------

aggregate is descriptive, not an estimate of application-level speedup.

Changes
-------
- Store subtree alias presence on powers, avoiding recursive power decoding.
- Skip ownership collection on ordinary copies and coefficient replacement.
- Use canonical byte comparisons for normalized expressions without aliases.
- Borrow surviving power bases instead of making unnecessary temporary copies.
- Outline alias-handle work and alias-specific sum normalization.
- Normalize raw transparent-alias bodies before merging into canonical parents;
  retain factors in aliased-product merges and preserve opaque behavior.

Method
------
Six paired rounds, seven approximately 100 ms samples per workload per round;
42 samples per workload/variant. Sequential binaries pinned to logical CPU 6
on an AMD Ryzen 9 5900X. No concurrent builds or tests during this final run;
normal desktop background processes remained active. Alias-free build order
rotated and live-alias order alternated. Setup/calibration is untimed; result
destruction is timed. Rust 1.99.0, release LTO, one codegen unit, native CPU
flags, identical dependency versions and default features across builds.

Reproduce with examples/alias_performance.rs, examples/global_alias_performance.rs
and benches/run_alias_performance.py; see benches/alias_performance.txt.
Full measurements, per-round ranges, provenance, binary hashes, and validation
logs are retained locally under benches/results/global-alias-2026-10-22/.
That generated-results directory is ignored by Git, following repository policy.
