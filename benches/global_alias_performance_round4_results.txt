Changes
-------
Both branches now use checked small-integer coefficient arithmetic before the
general number-domain implementations. The small inline dispatch avoids the
large stack frame of the general addition/multiplication fallback. The E-power
normalizer also compares the symbol directly, avoiding a temporary expression.
Overflow, complex, fractional, and infinite values retain their general paths.

Global avoids redundant alias cleanup work for ordinary atoms, simplifies the
alias flag test, and keeps root-alias structural comparison out of the ordinary
path. Public expression equality dispatches ordinary data straight to byte
comparison. Nested semantic equality compares ordinary children directly and
recurses only where alias semantics require it. Nested hashing writes expanded
function/product encodings into a shared buffer, avoiding intermediate encoding
buffers at each ancestor; sums retain their temporary encoding and ordering
buffers. Ownership context stays
live while alias bodies are borrowed. Arbitrary-hasher write sequences and
opaque-alias identity remain covered by tests.

Canonical packed headers remain an invariant. This pass removes unnecessary
checks for nonminimal encodings; it does not add support for invalid encodings.

Expansion now exposes transparent alias bodies at structural decisions, such
as an aliased sum under a power or inside a product. The new benchmark checks
found that these cases could previously return an unexpanded aliased expression;
that incomplete work must not be counted as an alias speedup. An independent
selective-is_expanded bug (a product returning early on an unrelated factor)
was fixed on main too. Main integration also updates the new evaluator/Horner
and MathML paths; MathML cursor replay retains alias body ownership and avoids
using a separate alias allocation as a raw cursor bookmark.

Final audit also found that polynomial expansion can miss aliased exponents
and open opaque aliases inside mixed expressions. expand_via_poly now delegates
alias-containing inputs to native expansion after its existing early exits;
ordinary inputs retain polynomial conversion. Tests cover aliased integer
exponents and opaque identity during whole-expression and selective expansion.
The performance of this fallback is not measured in this report.

Measurement method
------------------
Six rounds, three samples per workload, 100 ms target, CPU 6 (SMT sibling 18).
Variants run adjacent to one another for each workload; their order rotates
and is balanced across the six rounds. Times are medians of within-round
medians. Percentage changes use median within-round ratios, so they need not
equal the ratio of the displayed median times. Negative means less elapsed time.

The initial runs were affected by background CPU contention and are retained
only as diagnostic data. Final runs use compare_alias_workloads.py --quiet:
before each complete variant group, both logical CPUs must be below 15% busy
over a one-second observation and no rustc process may be present. A group is
retried if any run has process CPU/wall below 95%, sibling activity above 20%,
or rustc present before/after execution. Acceptance never uses operation timing.
All rejected groups, raw output, and telemetry are retained. This reduces
observable contention; it does not control CPU frequency or detect every brief
background process. Small percentage differences should not be overinterpreted.

Paired expansion with and without aliases
-----------------------------------------
The same shared harness constructs both representations. Setup asserts that
aliases remain compressed, that semantic input/output equality holds, and that
fully inlined input/result bytes match their ordinary counterparts. Independent
numerical formulas are checked at three points. Timed work is only native
expand(), including output allocation/destruction. This is not expand_via_poly.

Workloads:
  small power: (1+x+y+z+w)^7
  small product: (1+x+y)^3 * (2+x+z)^3 * (3+y+w)^2
  large power: P(x,y)^4, where P has 12 monomials
  repeated product: (P(x,y)^2+z) * (P(x,y)^2+w), sharing one aliased P
  P(x,y) = sum_{i=0..11} (i+1) * x^(i mod 4) * y^floor(i/4)

small power                308.6          359.0           363.3    +16.20%        +1.05%
small product              210.4          243.2           245.1    +16.31%        +1.08%
large power               2630.0         3099.6          3174.8    +17.46%        +3.26%
repeated product           807.6          955.9           962.2    +18.50%        +1.02%

Across these four cases, descriptive geometric-mean time is 17.11% higher for
global plain than main, and 1.60% higher for global aliased than global plain.
Observed aliased/plain round ranges are [-0.1%,+5.8%], [-7.4%,+2.7%],
[-2.7%,+10.6%], and [-0.2%,+3.4%]. These are observed ranges, not confidence
intervals. Incremental alias cost is close to parity; the precise 1–3% differences
are not established as robust regressions. The branch's underlying no-alias
overhead is the larger and more consistent cost.
